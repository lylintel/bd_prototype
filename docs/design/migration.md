# AXI-Stream 统一迁移契约

状态：评审已批准，实施中。此处集中定义 IP v2、设计 v5、ops v2 的升级及兼容策略；当前完成状态以 Phase 2B.1 报告为准。其他设计文档只引用本说明，不维护另一套迁移步骤。

## 设计 v5

- 旧文件照旧读取，不因打开、检查或保存普通编辑而自动升版。不回写输入文件；持久化仍显式保存。
- 由用户明确触发迁移/接受包含迁移的接口提案，先产生候选并预览，确认后一次原子历史提交。只有单向 v2/v3/v4 -> v5 升级，不提供隐式或自动降级。
- 迁移只添加接口字段，不重新解释原有参数、端点、slice/concat 位序或层次引用。子设计继续使用根的扁平定义表，不创建跨层路径端点。
- 没有接口的 v5 与同一设计的 v4，在相同 language/quality 模式下输出 HDL 必须逐字节相同，包括文件名、排序和注释头；HDL 头使用兼容投影版本，不用改变头部的方式破坏承诺。项目文件本身仍明确标 v5。
- 先建立无接口 golden 和迁移后序列化/读取往返测试，再实现其他能力。往返指迁移后保存/重开相同、取消无变化及 undo 恢复旧内存快照，不是支持 v5 文件降级。
- 总线连接是唯一事实来源。显示展开不改变语义；单信号修改前须明确物化整条连接，删除该总线连接并插入全部标量 nets，一次撤销可恢复。不能同时保存同一连接的总线与派生 nets。

## IP v2

- v1 继续严格验证并保持旧 schema/hash/文件字节；不自动批量更新库或历史元数据。
- v2 接口映射引用真实已解析端口，候选归组不等于确认。用户明确确认映射后登记，接口信息参与新版本指纹；旧 id/version 仍可解析，不覆盖旧目录。
- 新增已确认接口属于元数据能力变化，使用新的 IP 版本。源码未变时源 SHA 保持，不能伪造一次源码修改来升级版本。
- 旧 v1 metadata 可以继续被 v5 设计引用，普通无接口 IP 不强迫迁移。未确认的候选不允许用于总线连接或模型提案。

## Ops v2

- 信封明确 schema_version=2；v1 操作和历史回放仍按原 schema 验证，不猜版本、不放宽未知字段。
- 新 interface endpoint 仅参与接口 connect/disconnect，不得放进 concat/slice/const；混用拒绝。每提案最多展开 4096 信号，原操作/文档大小上限继续有效。
- ops 使用当前打开层局部名字；子层候选合回整根校验，并核对根快照、作用层和元数据指纹。共享定义不可由 AI 修改；不自动 clone、不接受越层引用。
- 常量绑定 fix 必须预览并由用户确认；确认之前不修改网表。需要标量修改的 fix 先显式物化，原子处理，不保留两份连接事实。

## 兼容证据

旧示例与全部历史 golden 不重录；新兼容测试直接与冻结 v4 字节比较。显式迁移、同模式生成、保存重开、取消/撤销、来源哈希和多实例层次引用分别验证。任何真实不兼容须先报告，不用更新旧 golden 掩盖。
